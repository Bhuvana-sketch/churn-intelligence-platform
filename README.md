# Customer Churn Intelligence Platform

**Python · Scikit-Learn · Power BI**

Analysed a 7,043-customer telecom dataset to uncover a **26.5% churn rate**, segmented
customers into **5 behavioural cohorts** using engineered engagement and risk-score
features, and designed a **5-page dashboard** and a **6-point retention playbook** to
translate the findings into actionable business recommendations.

**[View the live dashboard →](https://bhuvana-sketch.github.io/churn-intelligence-platform/dashboard/churn_dashboard.html)**

## Quickstart

```bash
git clone https://github.com/<your-username>/churn-intelligence-platform.git
cd churn-intelligence-platform
python3 -m venv .venv && source .venv/bin/activate      # optional but recommended
pip install -r requirements.txt

python scripts/01_feature_engineering.py     # downloads the dataset + builds features
python scripts/02_segmentation.py            # clusters into 5 cohorts + trains the model
python scripts/03_dashboard_datasets.py      # builds the dashboard cross-tabs
python scripts/04_build_powerbi_workbook.py  # rebuilds the Excel data model
```

Then open `dashboard/churn_dashboard.html` directly in a browser — it's a fully
self-contained file (Chart.js loaded from a CDN, all data embedded inline).

## Key findings

- **Overall churn: 26.5%** (1,869 of 7,043 customers)
- Engineered **Risk Score** correlates **+0.50** with actual churn; **Engagement Score**
  correlates **-0.34** — both validated before use, not assumed
- A Random Forest churn model reaches **AUC 0.85** on held-out data
- **5 cohorts**, ranked by churn rate:

  | Cohort | Size | Churn Rate | Profile |
  |---|---|---|---|
  | At-Risk Newcomers | 21.5% | 59.7% | New, month-to-month, low engagement |
  | Wavering High-Spenders | 19.6% | 29.3% | Mid-tenure, high spend, still at risk |
  | Disengaged Low-Spenders | 20.9% | 28.0% | Short tenure, fewest services adopted |
  | High-Value Champions | 21.1% | 8.2% | Long tenure, high spend, fully engaged |
  | Contract-Locked Loyalists | 17.0% | 2.5% | Long tenure, low spend, contract-locked |

- Top churn drivers (model feature importance): Risk Score (28.9%), month-to-month
  contract (16.7%), contract length (11.1%), monthly charges (8.2%), unprotected fiber
  service (8.0%)
- **At-Risk Newcomers alone represent ~$882K of estimated annual revenue exposure** —
  more than the bottom three cohorts combined

## Retention playbook (6 points — full detail in `docs/Retention_Playbook.docx`)

1. **90-Day Contract Migration Offer** — incentivise month-to-month customers onto annual terms
2. **Fiber Security & Support Bundle** — free trial of security/support add-ons for unprotected fiber accounts
3. **First-90-Days Onboarding Journey** — structured touchpoints for new, low-tenure customers
4. **Autopay Migration Incentive** — move electronic-check payers to automatic payment
5. **High-Value Concierge Save Desk** — proactive outreach for high-spend, high-risk accounts
6. **Service-Gap Cross-Sell Nudges** — lightweight add-on recommendations for disengaged, low-service customers

## Rebuilding the Power BI report natively

1. Open Power BI Desktop → **Get Data → Excel** → select `docs/Churn_Intelligence_DataModel.xlsx`
2. Load `Fact_Customers` as the main table, plus the `Summary_*` / `Dim_CohortSummary` sheets
3. Recreate the 5 pages using `dashboard/churn_dashboard.html` as the visual/layout reference:
   Executive Overview, Cohort Explorer, Churn Drivers, Revenue at Risk, Retention Playbook

## Methodology

- **Dataset:** [IBM Telco Customer Churn](https://github.com/IBM/telco-customer-churn-on-icp4d) — 7,043 customers, 21 raw fields, auto-downloaded by `01_feature_engineering.py`
- **Engagement/Risk scores** are hand-engineered, inspectable weighted composites (see `01_feature_engineering.py`), not black-box outputs
- **Cohorts** come from `KMeans(n_clusters=5)` on standardised features, then named from each cluster's realised profile rather than an arbitrary rank order
- **Random Forest** is a separate, complementary layer used for per-customer risk scoring — it does not drive the cohort definitions
